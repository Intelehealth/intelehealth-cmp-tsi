# Rule 6 control map

This maps DPDP Rules 2025 Rule 6(1)(a)–(g), and the other security-bearing obligations, to the control that discharges each one, where it lives, and who owns it. It is the document an auditor asks for first.

Two kinds of control appear here:

- **In the repo.** Enforced by code or by a database trigger, and covered by a test. These are marked *(code)*.
- **Outside the repo.** A deployment, procedure or contract. The repo cannot prove these. Each one names an owner, a record to keep, and a review cadence. Until the owner fills in the record, the obligation is **not** discharged.

> Owners are roles. Write a named person and a date next to each one before relying on this map. The DPO decision register (`docs/dpo_decision_register.md`) uses the same convention.

## Methods the code review did not cover

| Ref | Gap | What closes it | Owner |
| --- | --- | --- | --- |
| M-01 | Dynamic and penetration testing | An automated authenticated pen test (`python_port/pentest/`, 114 attacks over the real HTTP interface, two tenants) runs in CI on every push and can target staging. Results go in [PEN_TEST_REPORT.md](PEN_TEST_REPORT.md). An external authenticated pen test of staging, scoped in [PEN_TEST_PLAN.md](PEN_TEST_PLAN.md), is still required before go-live and after each major release. | CTO |
| M-02 | Dependency and supply-chain review | `python_port/requirements.lock` pins every runtime dependency with hashes (pip-compile); the image installs it with `--require-hashes`, and the `supply-chain` CI job audits that lockfile (`pip-audit --strict --require-hashes`), checks it covers `requirements.txt`, and refuses committed bytecode. The browser libraries are vendored and hashed in `web/vendor/README.md`. Refresh the lock monthly. | Engineering lead |
| M-03 | Web and transport hardening | The app sets CSP (`script-src 'self'`, `script-src-attr 'none'`: no inline script, no inline handler, no third-party script host), HSTS, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, COOP and Permissions-Policy *(code)*. The tokens are not in cookies, so there are no cookie flags to set. TLS versions and ciphers are set at the reverse proxy: run a TLS scan of the deployed host and keep the report. | Infrastructure lead |
| M-04 | Scope: the CMS only | Run the same review over the telemedicine platform that holds the health records. A compliant CMS does not make the fiduciary compliant. | CTO + DPO |
