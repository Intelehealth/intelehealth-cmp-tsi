Breach Notification Types

Define standard, category-specific messages (e.g. for a phishing incident vs. a theft incident) that you can pick from when reporting a breach. If you don't define any, breaches use a single generic message.

Notification Messages

Set the exact message a Data Principal sees for each event, in every language your active policy supports. Leave a language blank to fall back to the default label for that event. Changes apply immediately - including to notifications already sent.

English and all 22 Eighth Schedule languages are supported.

Webhooks

Push notifications and purge events to your own systems as they happen, alongside the existing poll-based APIs (nothing changes there). Each webhook is signed - verify the X-TSI-Signature header (HMAC-SHA256 of the request body, using your secret) before trusting a delivery.

Processor endpoints

Each processor (app) can receive withdrawals, erasure requests and purpose closures on its own endpoint, and must acknowledge its own alert. A processor without an endpoint can still poll its alerts with its API key.
